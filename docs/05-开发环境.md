# 开发环境
本文依据仓库中的 `backend/pom.xml`、`frontend/package-lock.json` 和运行配置整理。

| 组件 | 项目要求或配置 |
| --- | --- |
| Java | JDK 17 |
| 后端 | Spring Boot 3.3.2、Maven、JdbcTemplate、MySQL Connector/J |
| 数据库 | MySQL 8，默认库名 `campus_recycle`；验收时核对实际 CHECK 约束是否生效 |
| Node.js | 当前锁文件中的 Vite 8.3.0 要求 `^20.19.0` 或 `>=22.12.0`，不能仅凭“Node.js 20”判断兼容 |
| 前端 | Vue 3、Element Plus、ECharts、Vite；具体依赖版本以锁文件为准 |
| 地址 | 后端默认 8080；前端以 Vite 启动输出为准，通常为 5173 |

## 首次启动

1. 启动 MySQL，在空的新库中按顺序执行 `database/schema.sql`、`database/init_data.sql`、`database/views.sql`。演示数据脚本不是迁移脚本，不应在已有业务数据的库中重复执行。
2. 将 `backend/pom.xml` 导入 IDEA，选择 JDK 17，运行主类 `edu.campus.recycle.CampusRecycleApplication`。也可在 `backend` 目录执行 `mvn spring-boot:run`；两种方式选一种，避免占用同一端口。
3. 在运行配置中设置下面的数据库环境变量。配置中的 `your_password` 是占位符，须换成实际密码。
4. 在 `frontend` 目录执行 `npm ci` 按锁文件安装依赖，再执行 `npm run dev`，打开终端显示的地址。`npm run build` 用于检查并生成前端生产构建。

| 环境变量 | 默认值 |
| --- | --- |
| `DB_HOST` | `localhost` |
| `DB_PORT` | `3306` |
| `DB_NAME` | `campus_recycle` |
| `DB_USERNAME` | `root` |
| `DB_PASSWORD` | `your_password`（须配置） |
| `SESSION_COOKIE_SECURE` | `false`；HTTPS 环境可设为 `true` |

演示账号为 `student01 / user-demo-hash` 和 `admin / admin-demo-hash`，仅适用于已导入当前演示数据的库。已有账号密码不由更新文档重置。

## 会话、图片与时间

前端开发服务器将 `/api` 代理到 `http://localhost:8080`，浏览器通过同一个前端地址登录和使用系统。会话使用 Cookie，30 分钟无操作过期；后端重启后须重新登录。不要混用 `localhost` 与 `127.0.0.1`。同一浏览器的普通窗口共享登录身份，多身份验收可使用独立浏览器或独立隐私会话。

图片保存于后端启动工作目录下的 `uploads/photos`，数据库保存 `/api/photos/...` 地址。IDEA 与命令行应保持同一后端工作目录，避免切换启动方式后找不到旧图片。上传支持有效 JPG/PNG，单张不超过 5MB。

交接日期与回收预约按 `Asia/Shanghai`（北京时间）校验；数据库连接和 JSON 时间配置也使用该时区。MySQL 的服务器/会话时间应与业务时间保持一致，因为写入时间使用了 `NOW()` 和 `CURRENT_TIMESTAMP`。

## 已有库升级与验证

后端启动包含增补字段、部分约束及旧状态修复，具体边界见 [系统实现说明](06-系统实现说明.md)。启动账号需要这些升级所需的建表、改表和视图权限；启动升级不能代替完整迁移核对。删除未用字段采用单独的一次性脚本，不由应用自动执行。

后端测试在项目根目录执行 `mvn -f backend/pom.xml test`；接口演示可使用根目录 `demo.http`，先登录取得 Cookie 和 CSRF 令牌。手动验收和只读数据库检查见 [功能检查指南](11-功能检查与测试指南.md)，已有测试证据见 [测试说明](09-测试说明.md)。
