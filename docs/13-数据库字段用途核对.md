# 数据库字段用途核对

核对基准为当前建表脚本、前后端业务代码和统计 SQL，共 10 张表、80 个字段；不将本轮源码核对表述为已检查真实 MySQL 全部历史数据。字段仍在表中不等于没有冗余；本次只更新文档，不删列、不改业务数据。

| --- | --- | --- |

| users | role、status | 管理员/普通用户权限及账号有效性；暂无页面启停账号入口 |
| users | total_points | 当前环保积分余额，是流水汇总的受控冗余 |
| users | reputation_score、reputation_bonus_at | 当前信誉分及时间恢复进度，参与低信誉操作限制 |
| users | created_at | 注册时间、管理员用户查询与追溯 |
| categories | id、name、point_factor | 类别标识、发布/编辑选择与分类统计、回收积分计算系数 |
| categories | created_at | 自动记录类别创建时间，目前无页面展示、业务判断或统计依赖；属于可选追溯字段 |
| items | id、owner_id、category_id | 物品标识、发布人和类别关联；新发布/编辑必须选择类别，历史 NULL 兼容保留 |

## 冗余与精简判断

| 类型 | 字段 | 判断 |
| --- | --- | --- |
| 历史快照 | 订单金额、方式和交接安排；回收类别、贡献积分 | 事件发生时的值具有独立历史含义，应保留；类别系数改变后不能重算历史积分 |
| 汇总冗余 | users.total_points | 便于读取余额，需与 eco_point_records 在同一事务维护，并定期按用户求和核对 |
| 可推导关联 | trade_feedback.buyer_id、recycling_orders.applicant_id | 当前业务可由订单或物品推导，属于可精简冗余；本次保留且由后端校验一致性 |
| 参与人记录 | trade_orders.seller_id | 当前可由物品推导，现保留订单参与人语义；不能据此宣称无传递依赖 |
| 可选追溯 | categories.created_at | 当前对核心流程非必需；若追求最小结构可删除，但当前最终图忠实保留现有字段 |
| 独立流程 | 各表 status 与完成时间 | 分别描述物品、交易、预约、实际回收事件，含义不同；相关更新需事务同步 |

信誉的时间恢复目前不单独写入 `reputation_records`，因此不能仅按信誉流水求和重建全部 `reputation_score`。`source_id` 在驳回物品时为物品编号，在交易评价时为交易订单编号；当前没有统一来源类型列。

## 评价和积分写入

买家确认交易完成后再提交评价。后端在同一事务中插入 `trade_feedback`、将 `trade_orders.status` 改为 `REVIEWED`，并按评分调整卖家信誉：4—5 分加 2，1—2 分减 2，3 分不变。页面保留订单，显示“已评价”、评分和评价内容，不再提供重复评价入口。该流程改变信誉分，不产生环保积分。

环保积分来源为 `recycling_records`：完成回收时将重量乘类别系数并四舍五入为整数，保存 `contribution_points`，正积分同时写 `eco_point_records` 并增加 `users.total_points`。历史无类别使用系数 1；积分为 0 时保存完成记录，不写 0 分流水。回收完成、积分流水和余额更新在同一事务执行。

## 日期字段

前端 `meetingDate` 写入 `items.meeting_date DATE`；交易申请时复制到 `trade_orders.meeting_date`。当前后端不向 `meeting_day` 写入。旧星期值无法确定具体日期，不能自动补造历史日期；旧物品需编辑补选并重新审核，已有订单历史值保留。回收预约使用 `appointment_at`，实际回收使用 `recycled_at`。

## 已从当前结构移除的字段

| 表 | 字段 | 原因 |
| --- | --- | --- |
| items | original_price、estimated_recycle_price、condition_level | 未形成原价、回收估价或成色输入、展示、筛选与计算功能 |
| recycling_records | recycle_amount | 原流程固定为 0，未形成回收金额录入或结算功能 |
| recycling_stations | accepted_categories、phone | 未形成可收类别限制或回收点电话展示功能 |

`database/remove_unused_fields.sql` 用于已有库的一次性精简，先备份到三张存档表再删列，应用启动不会自动执行该删除。本轮未运行迁移；勿为同步文档重建数据库或重跑演示数据。验收库精简情况可用 `database/field_usage_check.sql` 只读核查，业务一致性另用 `database/integrity_check.sql`。
